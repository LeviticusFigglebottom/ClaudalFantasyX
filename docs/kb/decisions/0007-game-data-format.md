# 0007 — Game data tables are JSON; flags and editor-facing data are `.tres`

- **Status:** accepted
- **Date:** 2026-10-22
- **Roles affected:** Systems, Combat, Progression, Narrative, QA
- **Author role:** Lead

## Context
SPEC §5.2 allows `Resource` (`.tres`) or validated JSON/CSV. Data must be tunable without code, checkable by Python validators, and loadable by the headless engine and the balancing simulator.

## Decision
- **Tables** (skills, statuses, enemies, characters, encounters, items, shops, drop tables, Lattice boards) are **JSON** under `game/data/<domain>/<table>.json`, shaped as `{"<table>": [ {"id": ...}, ... ]}`. Python validates them in CI (`tools/validate_data.py`), and loaders index rows by `id`.
- **Flags** stay in `game/data/flags.tres` as the spec requires. The `flags` dictionary must stay JSON-compatible (string keys, string descriptions) so the validator can parse it.
- **Localization** uses Godot CSV translation files in `game/data/loc/`: `strings.csv` for UI and data, and `dialogue.csv`, generated by `tools/dlgc.py`.
- Editor-authored, scene-adjacent data (materials, themes, environment settings, animation libraries) uses `.tres`.

## Consequences
Diffs stay readable and merges are easy. Designers edit numbers without opening Godot. Every new table needs a validator section and a `BattleDB`-style loader.
