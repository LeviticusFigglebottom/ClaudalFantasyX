## Done
- **The write is checked before the rename** (`SaveSystem._write_checked`). The steps are store result, flush, `get_error()`, close, then a read-back compare. If any step fails, the tmp file is deleted and the error is returned, so the old save stays intact. `SaveSystem.store_text` is the injectable writer used to simulate failures.
- **Deep shape check** (`SaveShape`, `game/core/save_shape.gd`). It checks element types for every state key, and versions must be whole numbers. A single reader, `_read_save`, backs `load_from_slot`, `deserialize` and `slot_info`, so a load and a listing always agree. A malformed slot reads as corrupt, and `load_into_game` leaves `Game.state` alone.
- **The autosave is deferred** out of `Game.set_chapter`. It now goes `request_autosave`, then waits for a later frame and a safe point: no hold, router idle, tree unpaused. `hold_autosave(holder)` and `release_autosave(holder)` are the sequencer API. `FieldCameraDirector` holds the autosave while a scripted shot is held. `EventBus.new_game_started` (new) and `load_into_game` drop a pending request.
- **New Game confirm** when slot 0 holds a run. "Go back" is the default and `ui_cancel` also goes back. ADR 0017 is **proposed**: the Lead should accept it. Loc keys were appended to `strings.csv` in their own commit.
- Tests:

  - Updated: `test_autosave.gd` and `test_title_menu.gd`.
