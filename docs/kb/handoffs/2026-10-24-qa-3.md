- **`tools/validate_data.py` check_banned.** The per-file prefilter `banned_any()` is one regex, `guard(?:(?:term)|(?i:term)|...)guard`, so it matches exactly where any per-term pattern matches. Line breaks are not word characters, so a file with no match needs no line pass. A file with a hit runs the old loop, so the messages and their order are the same. The walk and the extension set are unchanged. I did not switch to `git ls-files`; the task notes say why.
- **`tools/tests/tree_mirror.py`** (new). `scratch_repo(prefix)` makes a unique /dev/shm dir (or `HYMN_TEST_TMP`), copies `game/` and symlinks each file under `assets/`. test_validate_data, test_items_validate and test_lattice_validate use it.
- **`tools/tests/test_audio_loudness.py`.** The same three tests and the same measurement calls, now through a process pool (`HYMN_TEST_JOBS`, default min(4, CPUs)) and a content-hash cache (`HYMN_TEST_CACHE`, default `~/.cache/hymn-undertow/audio_loudness`, `off` to disable). Writes are atomic (mkstemp + os.replace), so parallel agents can share the cache.
- **`tools/run_tool_tests.py`** (new). It runs one process per module, splits test_rig_integrity per TestCase class, starts the heavy units first, and prints a failing unit's full output. The total must equal `unittest discover`'s count or the run fails. `tools/ci_local.sh`'s "Tool unit tests" step now uses it. CI's `ci.yml` still runs plain discover, which works unchanged.
- **`tools/tests/test_banned_scan.py`** (new, 7 tests). Seeded terms in .gd, .md and .json are caught. .png, .glb, .ogg, .wav, .res and .png.import are ignored, and so is a .md outside the scan. It also covers case flags, whole words, CRLF and Unicode line breaks, invalid UTF-8, and the single-file glossary entry. Every case is checked against a copy of the old scan, and the combined regex is checked against the per-term patterns for every term.
