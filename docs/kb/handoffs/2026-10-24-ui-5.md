# Handoff — ui — 2026-10-24 #5

## Done
- **M1-UI-11 is in review (reviewer: architect).** With `GraphicsRuntime` armed, a Graphics-page preset change now does these steps:
  1. It fades an opaque veil in, with the "Applying the preset…" card (`GFX_MENU_APPLYING`).
  2. It lets one opaque frame draw.
  3. It calls `select_preset`, which spawns the resident `ShaderPrewarm`.
  4. It holds, with all input swallowed, until the warm-up's `finished` fires or the node frees or stops running.
  5. It fades back.
- `GraphicsRuntime.last_warmup` is a new static var: the node that `warm_resident_shaders` returned.
- Setting overrides spawn no warm-up, because tiers follow the preset id. This is documented in `docs/kb/tech/graphics_settings.md` under "The Graphics menu".
- There are new tests in `tests/unit/test_graphics_menu_apply.gd` (3), and `tools/tests/test_graphics_menu_data.py` now checks the card key.

## Known issues
- `apply.max_hold_sec` (8 s) is a safety net only. A warm-up that hangs while it is running would hold the veil that long.
- An in-game pause menu would want the same veil for override-side costs, such as a shadow-atlas resize or SDFGI re-converging. There is no pause menu yet.
